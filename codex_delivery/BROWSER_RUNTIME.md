# Offline public browser VM candidate

This candidate is separate from the offline work runtime. It must pin a distinct `browser-qemu-v1` asset kind and guest protocol; a working document guest is never accepted as a browser guest. The existing Landlock and readonly-jail profiles keep their previous behavior. A missing feature never selects a weaker profile automatically.

A fresh TCG VM has no virtual network device, account storage, private task input or workspace disk. Its readonly configuration contains only the already approved public navigation URL, screenshot choice and bounded runtime parameters. A fixed guest root supervisor owns the root-only virtio serial port. A fixed Node CDP driver runs as uid 65531; Chromium and its renderer run as uid 65532 with no capabilities and no-new-privileges. Chromium's own namespace/seccomp sandbox stays enabled. Root creates only the two fixed CDP pipes shared with those processes; renderer and driver never inherit the export serial port. The supervisor never executes page or model code.

The host retains the authenticated Controller grant and `PublicFetchBroker`. The guest receives no grant scope, identity, lease, callback token, caller headers, request body, cookie or account profile. Its fixed driver supports navigation, request interception, title/text/link extraction and a 1280-by-900 PNG screenshot. No click, login, upload, arbitrary evaluation or profile argument is exposed.

The virtio channel is duplex over the native helper's existing standard descriptors. Host stdout is the preopened exact export file required by readonly-jail; the parent incrementally reads its framed stream. Responses return through the existing stdin pipe. No additional host descriptor, socket, device, mount or capability is needed. The wire protocol begins with `CWB1\n`; each following frame is a bounded big-endian length and a closed JSON object. Fetch frames contain only kind, monotonically increasing id, exact URL and GET/HEAD method. Unknown keys, duplicate/replayed IDs, malformed frames and more than 64 requests fail closed. Responses contain only the matching ID and bounded status/content type/redirect/body or a stable error code. Redirect targets require a fresh exact-grant and DNS check through the host broker.

Budgets are at most 2 MiB per resource, 16 MiB total fetched body, 8 MiB per frame, a 16 MiB hard output spool, and an explicitly selected 120-second complete VM lifecycle. The operation receives at most 114 seconds, with six seconds reserved for confirmed stop and cleanup; the remaining grant lifetime shortens the entire lifecycle. A grant with no remaining operation budget is refused before launch. The guest bridge independently stops after 95 seconds; individual HTTP/CDP/navigation deadlines remain shorter. There is no timeout fallback or extension beyond the original grant. The parent validates the fixed result shape, URL, string/link limits, Base64, PNG signature/IHDR and screenshot dimensions. After validating the final result, the host sends a fixed result acknowledgement before the guest powers down. Nonblocking channel writes handle partial progress and backpressure. It returns a result only after confirming the VM has stopped. A fresh guest profile exists only in bounded guest tmpfs and disappears with the VM.

Initial qualification uses a 2 GiB physical guest and bounded tmp/profile storage. Node's address-space budget and Chromium's much larger reserved virtual address space are separate from guest physical RAM; V8 virtual reservations must not be mistaken for resident memory. Signed Debian package inventory and complete runtime asset digests bind the Chromium ELF, Node, fonts and guest kernel. The first gate is a normal offline Chromium launch with its own sandbox enabled, followed by synthetic broker/HTML and cancellation/expiry/limit tests. No HA browser qualification or formal deployment is implied by a local smoke.

Production host resources remain a separate unresolved gate. `native-resource-v1` is being evaluated as an explicitly selected alternative to the tested finite-cgroup composition: a fixed logical-CPU affinity, hard address-space/thread/CPU/file/FD limits, no process fork or namespace creation, and a similarly bounded trusted parent. RLIMIT_NPROC's user-namespace and shared-real-UID behavior, QEMU virtual-address requirements, limit locking and actual stop behavior require direct qualification. CPU affinity means a maximum number of simultaneously usable logical CPUs; it is not described as an equivalent cgroup average quota. Existing cgroup qualification cannot be bypassed while that new profile is unqualified.

The fixed synthetic browser qualification now passes the complete seven-test group in a local TCG fixture and on an independent HA fixture with real host-boundary checks. It covers a Chinese page, fixed JavaScript producing 42, a real 1280-by-900 PNG, ungranted requests rejected before the broker, strict framing, incompatible work-guest rejection, insufficient-grant refusal and a short grant that starts a VM and confirms its stop without retained run files. The screenshot digest agrees across the two environments. The HA fixture uses docker-default, a nonroot user, no capabilities, no-new-privileges, a readonly root, no network/mount/device, and finite CPU/memory/PID limits. Its outer seccomp is explicitly unconfined to match Supervisor; the native helper installs its own filter. The temporary fixture is removed after qualification. These results do not qualify a permanent Supervisor resource composition, task cancellation during a synchronous DNS/HTTP call, or production installation. The trusted-worker contract in `TRUSTED_WORKER.md` describes the remaining cancellation gate.

The separate `native-resource-v1` candidate has subsequently passed local real-VM document/Node and browser qualification. Its trusted test parent installs hard AS3GiB/NPROC32 and two-CPU affinity before loading the suites; QEMU then receives its own locked per-VM limits. The native browser tests cover the same rendered PNG, real VM plus broker cancellation during blocked DNS, confirmed stop, permanent grant revocation, short-grant expiry and no worker replacement. Separate real-process tests cover normal HTTP, blocked DNS and HTTP-body cancellation. A unit fault injection confirms unconfirmed cleanup freezes the backend and retains owner handles. Desktop replaces only its unavailable AppArmor assertion in these local fixtures; all native resource and isolation mechanisms execute. Target HA native-profile qualification and permanent composition remain uncompleted gates. The earlier HA cgroup result does not qualify this different resource profile.

An independent HA native-profile run passed the fixed C resource self-test and 14 of 16 checks, including actual browser rendering, VM-plus-worker DNS cancellation, short-grant stop, Node and both Chinese document styles. It exposed two real HTTP-worker failures: the broker's internal Timer could not start under shared-UID NPROC accounting. This failure was reproduced locally with two additional same-UID processes. The corrected candidate keeps the worker's hard limit unchanged and moves its at-most-eight-second request deadline to the pidfd owner; only that worker disables the Timer. Real-process tests now cover that shared-UID load and dripping HTTP headers/body through deadline and cancellation. These local fixes require a new complete target qualification; the partial HA run must not be represented as a passed native composition or a production installation.

The corrected local candidate also passes a real VM browse through the actual broker worker and HTTP response path, with only its fixed test transport substituted. A Chinese page without a meta charset declaration renders correctly from its Content-Type charset, runs the fixed page script, and returns a real PNG; no Cookie/Authorization is sent, and both worker and VM terminate. The fixed loopback transport exists only in the test fixture and cannot be selected in production.
