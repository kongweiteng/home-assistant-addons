# Independent work runtime library

`codex_work_runtime` contains no Controller account, node identity, canonical lease, callback token, task database, or private Runner dependency. Its `WorkRuntimeError` exposes a stable `code`, short sanitized message, and `uncertain` flag. Installing this library into the metadata image does not enable execution or select any runtime.

Trusted composition provides these interfaces:

- `WorkRuntime` registers an immutable runtime reference, explicit kind and interpreter contract. Work accepts only document/data/code with Python or Node; browser accepts only browser with fixed JSON intent; preview has a distinct app contract. The optional Docker backend rejects browser/preview kinds. For QEMU, `image` is the full generated asset-manifest SHA-256, not a Docker image identifier. The helper SHA and compiled isolation profile are transitively pinned by that manifest.
- `WorkLimits` and `WorkRequest` carry administrator-fixed limits and canonical owner/task/workspace, revision, assignment epoch and expiry. Model code cannot choose host paths, mounts, backends, capabilities or credentials.
- `WorkExecutor(state_root, backend).execute(request, program=..., inputs=...)` fences concurrent/replayed/conflicting claims and keeps an execution journal. Only a stopped backend's durable validated checkpoint can become a receipt. Interrupted or uncertain claims require reconciliation and do not rerun automatically.
- `QemuWorkBackend(runtimes, assets, state_root, policy=...)` launches an offline TCG VM through a fixed native helper. It checks actual Linux uid/capabilities/NNP/AppArmor/cgroups, fixed assets, and native qualification. It uses no Docker API, host mounts, device, KVM, account storage or network interface. Qualification currently requires the exact tested AppArmor profile; a different production composition must be separately qualified.
- `WorkExecutorAdapter` bridges canonical task/lease/identity gates and fixed registered runtimes to the executor. Delivery remains the task and authorization authority. Callback and lease credentials stay in trusted composition, outside the guest.
- `public_browser` is a separate, exact-grant read-only browsing adapter. It does not give an offline work guest a network device or browser account. Its own sandbox and grant/expiry gates must pass before browser qualification.
- `AuthorizedPublicBrowser(browser, callback.resolve_browser_grant)` in `browser_adapter` obtains a fresh authenticated Controller grant before every navigation. The independent runtime validates the closed response against the canonical task scope and exact URL list. Grants expire using both wall and monotonic clocks within five minutes; source text, pages and task programs cannot issue them. Public fetches use a total header/body deadline, public DNS answers and a numeric pinned connection. URLs stay literal, so browser normalization to an ungranted variant fails closed. Link extraction never grants navigation.
- `validate_browser_result` validates the closed fixed-driver result, bounded text/links, and a bounded PNG with the fixed 1280×900 viewport. A distinct offline QEMU browser guest has passed local and HA synthetic page tests; its permanent resources and updated cancellable broker still require qualification.
- `BrowserWorkBackend` accepts exactly `version/url/exact_urls/screenshot` as the program JSON. It executes no task JavaScript on the host, resolves the original task from Delivery, and obtains a fresh human-source grant via `AuthorizedPublicBrowser`. Fixed report.txt/page.png then pass through the same WorkExecutor journal, source/output archives and Controller upload. Cancellation reaches the VM/broker callback. Known stopped cancellation archives an empty checkpoint; unknown stop retains the unsettled execution. Local composition tests use real Controller HTTP/AES/journal with an explicitly synthetic VM.

The optional `DockerWorkBackend` is for an explicitly qualified external execution node. It must not give an HA Add-on a Docker socket. QEMU's readonly-jail and Landlock helpers are independently compiled profiles; an unavailable kernel feature never causes an automatic downgrade.

Common credential-free native/guest/build sources and synthetic qualifications are in [runtime-build](runtime-build/README.md). Public tests import this same single-source library. The metadata service remains fail-closed until the selected production composition, private persistent state, independent backup, recovery, input/artifact callbacks, browser and deployment boundaries have passed their separate acceptance gates.
