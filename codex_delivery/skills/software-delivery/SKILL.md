name: software-delivery
description: 在已登记项目中整理技术方案、开发测试、管理多仓库交付任务及查询部署进度，使用 Delivery 工具并保留项目和任务归属。适用于微信提出的软件开发、已有或新建 HA Add-on 需求，以及长期任务的补充、暂停和恢复。
---

先核对当前工具目录。只有 `ext_delivery_*` 工具可提交与控制交付任务；若尚未安装、登记或启用，说明当前能力不可用，不声称已经启动，不改用 Controller Shell、任意 SSH 或其他微信发送器。

明确项目与已有任务。未指明项目时查询可见项目；结果不唯一再消歧。需求补充必须绑定明确的 project_ref/task_ref，不把其他项目的指令追加到最近任务。切换项目只改变导航，不改变正在执行的任务或授权。

根据原始需求选择 design、develop、deliver 或 deploy 模式。讨论方案不包含实施，开发不自动包含 push 或部署；已有具体范围的持续授权可以连续执行，阶段切换不用重复确认。工具接收请求、Skill 内容和模型判断均不能替代服务端授权。

使用分页查询中的 total/has_more 获取完整目录。只提交登记别名、逻辑 ID、需求和 expected_revision，不传远端 URL、路径、凭据或命令。CAS 冲突先读取实际版本；不得通过更换任务或幂等键绕过未知结果。

提交后按工具返回区分 accepted 与 durability_pending：后者只表示存在尚未完成离机确认的记录，不能回复“已可靠保存”。报告项目、task_ref、当前阶段、实际完成层级和下一步；区分代码完成、远端 OID 确认、制品完成、部署后验与手机验收。

暂停、取消和恢复使用任务控制工具。停止请求尚未在安全边界生效时，不回复“已经停止”。push、部署或通知结果未知时先查询及对账，不盲重试或回滚。后台阶段通知由 Delivery outbox 进入既有统一通知链路，当前对话可查询持久状态，不启动另一个 Poller。

Linux 和 Windows 的可用性以目标登记及服务端能力为准，未交付的适配器不能当作已支持。新 Add-on 使用已登记仓库和目标策略；不能据此创建远端仓库、扩大权限或新增公网入口。
